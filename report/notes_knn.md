## Interpretation bullets (for the report)

- **What was tuned.** `Pipeline(make_preprocessor(), KNeighborsClassifier)` with `GridSearchCV` over K ∈ {5, 7, 9, 11, 15, 21, 31, 41, 51, 71, 101, 151} (odd values, so uniform votes never tie) × weights ∈ {uniform, distance} = 24 settings × 5 stratified folds, scoring = ROC AUC, seed 2607526, `n_jobs=2`. The whole grid took 16.6 s (brute-force neighbour search on 32 preprocessed columns is vectorised), so no subsampling was needed. StandardScaler + one-hot live inside the pipeline and are refitted in every fold, so no fold ever sees validation statistics.
- **Best setting: K = 101, uniform weights, CV AUC 0.7700 ± 0.0087.** CV AUC rises monotonically from K=5 (0.706) to K≈101 and then flattens (K=151: 0.7688), i.e. the optimum is well inside the grid, not on its edge (see `figures/knn_cv_auc_vs_k.png`). Uniform weighting beats distance weighting by a small but consistent 0.001–0.004 at every K, so the ranking is stable across the grid. A one-standard-error rule would already accept K ≈ 51 (CV AUC ≥ 0.7613), which shows how flat the curve is beyond K≈50.
- **Why such a large K.** Default is a noisy, low-signal outcome (22 % base rate, heavily overlapping classes), so the local class proportion has to be estimated from many neighbours before it is a usable probability. With K=5 the vote is a 0/0.2/…/1 step function that overfits the training set (train AUC 0.883 vs test 0.709); with K=101 the estimate is smooth (train AUC 0.787, OOF AUC 0.770, test AUC 0.771 — practically no optimism gap). The strong preference for large K is the same message as the LDA/logistic results: the signal in this data set is mostly a smooth, global one.
- **Effect of tuning (the course default vs the tuned model).** K=5/uniform ranks 23rd of 24 settings in the grid: test AUC 0.7087 → 0.7706 (+0.062), AP 0.4215 → 0.5423 (+0.121), Brier 0.1612 → 0.1361, log-loss 1.033 → 0.434. The K=5 log-loss is so poor because it emits hard 0/1 probabilities for many clients; its ROC/PR curves have only 6 operating points. Untuned KNN is clearly worse than logistic regression; tuned KNN is slightly better.
- **Comparison with the logistic baseline.** Tuned KNN edges out logistic regression on the threshold-free metrics: test AUC 0.7706 vs 0.764 (+0.007), AP 0.5423 vs 0.524 (+0.018). Both gains are of the same size as the fold-to-fold CV standard deviation (0.0087), so they should be reported as "comparable, KNN marginally ahead" rather than as a decisive win. The likely source of the small edge is the non-linearity KNN can capture in the PAY_x / utilisation region (e.g. the jump between "paid duly" and "1–2 months late") that a linear logit can only approximate.
- **Operating points.** At the default 0.5 threshold KNN is accurate (0.8196 > majority-class 0.779) but catches only 34 % of defaulters (recall 0.3424, precision 0.6844). Moving to the F1-optimal threshold 0.25 — chosen on training out-of-fold probabilities, never on the test set — lifts recall to 0.5963 at precision 0.4952 (F1 0.5411, accuracy 0.7762); the 5:1 cost-optimal threshold 0.16 pushes recall to 0.7476 at precision 0.3544 (test cost 5,219 vs 6,854 at 0.5). Threshold choice matters far more than the last 0.01 of AUC for a lender.
- **Why scaling was necessary.** Euclidean distance is only meaningful if every column contributes on a comparable scale. Raw LIMIT_BAL and BILL_AMT are in the tens of thousands of NT$, while PAY_x is in −2…8 and AGE in 21…79; unscaled, the distance is dominated by the bill amounts and the informative repayment-status columns are ignored. The ablation in `results/knn.json` (`extra.ablation_unscaled_same_K`) makes this concrete: the same K=101/uniform model with `make_preprocessor(scale=False)` drops from CV AUC 0.7700 to 0.6585 (−0.11), i.e. below the untuned K=5 model with scaling. Unlike trees, KNN has no invariance to monotone rescaling, so StandardScaler inside the pipeline is part of the model, not a cosmetic step.
- **Why KNN is slow (lazy learner).** Training is just storing the 20,975 × 32 standardised training matrix (5.37 MB; `fit_seconds` 0.027 s). All work happens at prediction time: every test row must be compared with every stored training row (O(n_train · n_test · d), brute force since a KD-tree degrades in 32 dimensions). Scoring the 8,990 test clients took 0.379 s (≈ 23,700 rows/s) versus 0.0055 s for logistic regression on the identical preprocessed data — about 69× slower — and the cost grows linearly with the size of the historical portfolio, whereas a logit's prediction cost is constant (33 multiplications) and its model is 33 numbers rather than the whole customer file. For a bank scoring millions of accounts nightly (or in real time at the point of sale) this, plus the need to keep the full training data online, is the practical objection to KNN even when its AUC is competitive.
- **Caveats.** (i) The tuned-vs-logistic AUC gap (+0.007) is within CV noise; a paired test on the saved `results/*_p_test.npy` vectors (e.g. DeLong) would be needed to claim significance. (ii) Distance is plain Euclidean on the shared preprocessor: the one-hot SEX/EDUCATION/MARRIAGE dummies get the same weight as a numeric column, and the very right-skewed BILL/PAY amounts are standardised but not log-transformed, so a few extreme balances still stretch the distance metric — a log1p transform or a learned metric was out of scope for the shared contract but is the obvious next step. (iii) KNN gives no coefficients or feature importances, so it adds nothing to the explanatory side of the report; its role is a non-parametric benchmark for the parametric models. (iv) Prediction timings are single-laptop wall-clock medians of 3 runs with 2 threads and will vary slightly between runs; the metrics themselves are fully seeded and reproducible.
