The headline 0.7506 / 0.5063 only exists because of residual coefficients below 2 × 10⁻⁴ left by libsvm's stopping tolerance and should not be quoted as a robust property of the model (bullet 3).

## Interpretation bullets (for the report)

1. **What was tuned, and why on a subsample.** libsvm's SMO solver is O(n²)–O(n³) in the number of rows, and with a linear kernel its cost explodes with C: on the 4,800-row CV folds the mean number of SMO iterations for the balanced linear kernel went 7.7 k → 13.7 k → 31.7 k → 4.87 M from C = 0.01 to C = 10 (mean fit time 0.3 s / 0.3 s / 0.5 s / 17.8 s), and C = 10 hit the 5-million-iteration cap in 3/5 folds (balanced) and 5/5 (unweighted) — hollow markers in `figures/svm_linear_cv_auc_vs_C.png`. All hyper-parameters were therefore tuned by 5-fold CV (ROC AUC, `cv=CV`, `scoring=SCORING`, `n_jobs=2`) on a **stratified subsample of 6,000 training rows** (`train_test_split(stratify=y_train, random_state=SEED)`, default rate 0.2213 = the training rate) and the chosen setting was then **refitted on the full 20,975-row training set**. Grids exactly as prescribed: linear kernel C ∈ {0.01, 0.1, 1, 10}; RBF C ∈ {0.1, 1, 10} × γ ∈ {'scale' (= 0.036), 0.01, 0.1}; both crossed with class_weight ∈ {None, 'balanced'} — 8 + 18 settings × 5 folds, every fit a `Pipeline(make_preprocessor(), SVC)` so the scaler and one-hot encoder are refitted inside each fold. Tuning used the decision function (`probability=False`): AUC is invariant to the monotone Platt sigmoid, so it is the same ranking at one-sixth of the cost. Selection rule for both kernels: one-standard-error rule on CV AUC (most regularised converged setting within sd/√5 of the best); in the event the arg-max and the 1-SE pick coincided for both kernels. Because the subsample is slightly "easier" than the full training set, the script also cross-validates the plain logistic baseline on the same 6,000 rows: **0.7650 ± 0.0098** (vs 0.760 on the full training set); that value, not 0.760, is the reference line drawn on both tuning figures.

2. **Best settings, and `class_weight='balanced'` is not optional (both numbers, as required).** Linear kernel: C = 0.01 with class_weight = 'balanced', subsample CV AUC 0.7629 ± 0.0049; the curve is flat in C (0.7597 at C = 0.1, 0.7575 at C = 1, 0.7576 at C = 10, the last one non-converged). RBF: C = 1, γ = 0.01, class_weight = 'balanced', CV AUC 0.7681 ± 0.0055; the balanced heat-map (rows C = 0.1 / 1 / 10, columns γ = 0.01 / 'scale' / 0.1) reads 0.7648 0.7638 0.7552 | 0.7681 0.7660 0.7541 | 0.7635 0.7426 0.7061: flat for small γ and C ≤ 1, falling off sharply in the most local, least regularised corner (C = 10, γ = 0.1: 0.7061) — a smooth, almost-linear kernel is what the data want. Unweighted, the best RBF cell reaches only 0.7311 (C = 1, γ = scale) and the best linear-kernel cell 0.7147 (C = 0.01); with balanced weights the same grids give 0.7681 and 0.7629 — **+0.037 and +0.048 AUC**. AUC is a ranking metric, so re-weighting should not matter for a model that estimates posteriors; it matters here because the hinge loss does not estimate posteriors: with a 22 % minority the unweighted margin is placed where the majority class dictates, most defaulters become bounded support vectors (α = C) on the wrong side, and the decision function stops discriminating among them. Balanced weights (C × 2.26 for defaulters, C × 0.64 for non-defaulters) move the margin into the overlap region where defaulters live. The balanced variants were kept for both kernels; the unweighted grids are in `extra.cv_table` and in the left panel of the heat-map. Both chosen values sit on the lower edge of the prescribed grids, so the script probes beyond them (reported only, never used for selection): linear C = 0.001 → 0.7533, C = 0.0001 → 0.7257 (worse — the optimum really is near 0.01 on 4,800-row folds); RBF γ = 0.003 → 0.7672, γ = 0.001 → 0.7650 (flat — γ = 0.01 is fine).

3. **The linear-kernel SVM is effectively a single-feature (MAX_DELAY) ranker — read its headline numbers with the CAUTION above.** Refitted on the full training set at C = 0.01, the max-margin solution puts all of its weight on one feature: `coef_` has ‖w‖ = 1.0802 with MAX_DELAY = 1.0802 and the other 31 coefficients below 10⁻³ — 30 of 32 are below 2 × 10⁻⁴ and the largest of the other 31 is 2.0e-04; 18,979 of the 20,975 training rows sit exactly on the margin (|s| = 1 ± 10⁻³). The liblinear hinge-loss twin in `svm_linear_calibrated` (`extra.hinge_loss_variant`) converges to that exact optimum — 9 distinct training probabilities, MAX_DELAY share of ‖w‖ = 100% — and agrees with the libsvm model to 1.1e-04 in probability. libsvm stops at tol = 10⁻³ and leaves sub-2 × 10⁻⁴ residual coefficients that happen to point along informative features (EDUCATION_4, UTIL_1, UTIL_MEAN, N_MONTHS_DELAYED); they break the ties inside the 9 MAX_DELAY clusters and are the *only* reason the model emits 344 distinct test probabilities (modal value on 6.8% of the test set) instead of 9. Rounding the test probabilities to 3 dp removes them: 9 distinct values, **test AUC 0.7202 / AP 0.3987, identical to MAX_DELAY alone** (0.7202 / 0.3987); on the training OOF the same rounding gives AUC 0.7106 (MAX_DELAY alone 0.7139). So the honest statement is: the linear-kernel SVM ranks like MAX_DELAY alone (AUC ≈ 0.72); the 0.7506 / 0.5063 in the table is that single-feature ranker *plus* solver residue that happens to be informative, and it beats the single feature only because of that residue — not a robust property of the model. Ties cost AUC directly (a tied pair counts ½), which is why the exact optimum sits so far below every other model. The same degeneracy explains a sanity check that otherwise looks alarming: the pooled OOF AUC 0.7167 is 0.0339 below the test AUC and 0.0461 below the subsample CV AUC. Inside each of the 5 outer folds the OOF AUC averages 0.7487 ± 0.0111 (`extra.oof.per_fold`: 0.7645, 0.7301, 0.7533, 0.7487, 0.7469) — consistent with the test value — but each outer fold is scored by its own (SVC, Platt sigmoid) pair, and five slightly different sigmoids place the near-tied MAX_DELAY clusters at slightly different probabilities, so when the five folds are pooled the clusters interleave and the ranking degrades by 0.0319. For a score with thousands of distinct values this pooling artefact is negligible: pooled minus within-fold mean is -0.0029 for the RBF and -0.0002 for the squared-hinge model. It is not overfitting (train AUC 0.7485 ≈ within-fold OOF 0.7487); it does mean the F1/cost thresholds for this model were tuned on slightly inconsistent probabilities, one more reason not to lean on it.

4. **Did the RBF kernel help?** Against the libsvm linear kernel, yes but mostly by not being degenerate: CV 0.7681 vs 0.7629, within-fold OOF 0.7635 vs 0.7487, test AUC 0.7616 vs 0.7506 (+0.011), and 7,790 distinct test probabilities instead of 344. Against logistic regression, **no**: test AUC 0.7616 vs 0.7636, AP 0.4944 vs 0.5234, Brier 0.1448 vs 0.1383, log-loss 0.4553 vs 0.4402. The RBF's train AUC 0.7841 vs pooled OOF 0.7606 shows a small optimism gap (0.024). The rankings of the RBF SVM and logistic regression are strongly correlated (Spearman ρ = 0.83 between the two saved `p_test` vectors, computed from `results/svm_rbf_p_test.npy` and `results/logistic_p_test.npy`), so the kernel is not finding a different kind of structure — it approximates the same smooth, mostly additive signal (PAY_x, MAX_DELAY, N_MONTHS_DELAYED, utilisation, LIMIT_BAL) with 13,140 stored rows instead of 33 coefficients. Tuned KNN (test AUC 0.7706, AP 0.5423) remains the best non-parametric model in the project.

5. **Comparison with the logistic baseline, and why the SVMs do not beat it (hinge vs log loss).** Logistic regression minimises log-loss: every client contributes in proportion to how wrong its probability is, so the score is a calibrated, smoothly spread posterior — exactly what AUC/AP reward. The SVM minimises hinge loss: a client beyond the margin contributes nothing, a client inside contributes linearly, and the objective only cares about the *sign* of the margin, not about ordering within each class. Hinge is not a proper scoring rule, and on a heavily overlapping problem (65.1 % / 62.6 % of all training rows end up as support vectors — the "sparse" SVM is gone) it produces poorly spread scores; bullet 3 is the extreme case, where the strongly regularised hinge optimum collapses onto one feature. Replacing hinge by **squared hinge** (sklearn's default `LinearSVC` loss — smooth, closer to log-loss) at the same C spreads the coefficients over the same features logistic regression uses (EDUCATION_4 -0.30, N_MONTHS_DELAYED +0.26, MAX_DELAY +0.19, UTIL_MEAN +0.12, LIMIT_BAL -0.09, UTIL_1 -0.09, …) and recovers logistic-level ranking: full-training-set CV AUC 0.7611, test AUC 0.7627, AP 0.5150 — versus 0.7266 CV AUC for hinge at the same C (`extra.full_train_cv_over_C_and_loss`; dashed vs dotted line in the C figure). The lesson for the report: a linear SVM and a logistic regression share the same hypothesis class w·x + b and differ only in the loss; for *ranking* a noisy 22 % outcome the log / squared losses win because they use all the data, not just the margin.

6. **How the SVM decision boundary relates to logistic regression, and the operating points.** Both linear models produce a score s = w·x + b and a boundary s = 0; the SVM's w is the max-margin direction determined by the support vectors, logistic's w is the maximum-likelihood direction determined by all points. The SVM score is not a probability, so probabilities had to be added by **Platt scaling**, which is literally a one-variable logistic regression of y on s fitted on out-of-fold scores (p = 1/(1 + exp(a·s + b)); a = -0.78, b = 1.16 for the linear kernel, a = -0.97, b = 1.11 for the RBF, a = -2.33, b = 1.21 for the squared-hinge model). Consequence: with balanced class weights the raw boundary s = 0 sits near a 50/50 effective prevalence, but Platt scaling pulls the probabilities back to the true 22 % base rate and they rarely exceed 0.5 (the RBF's largest test probability is 0.63), so the **default 0.5 threshold is useless for the libsvm models** — recall 0.1111 (linear) and 0.0729 (RBF) at accuracy 0.7881 / 0.7842, i.e. no better than the majority class. At the F1-optimal thresholds tuned on training OOF probabilities (0.24 linear, 0.42 RBF, 0.30 squared-hinge) recall rises to 0.5887 / 0.5681 / 0.5752 at precision 0.4686 / 0.5160 / 0.5040, F1 0.5218 / 0.5408 / 0.5372. The RBF's tuned F1 (0.5408) is on a par with the best models in the project but not above them (logistic 0.5360, KNN 0.5411). Under the 5:1 cost criterion (thresholds 0.13 / 0.12 / 0.15) the test costs are 5,132 / 5,155 / 5,203 versus 5,126 for logistic — all within a few dozen units of each other.

7. **Why SVMs are expensive here, in numbers (all from the JSONs of this run).** (i) Training: libsvm needs the kernel matrix — 20,975² float32 = 1.8 GB, so even with a 1 GB cache rows are recomputed — and its cost grows roughly ten-fold per decade of C (bullet 1; at C = 10 the linear kernel hit the 5 M-iteration SMO cap in 3–5 of 5 folds on 4,800-row folds). The final Platt-scaled fits (5 CV fits + 1 refit each) took 24.6 s (linear, 13,677 SMO iterations) and 47.3 s (RBF, 27,778 iterations), against 0.44 s for logistic regression; the nested out-of-fold probabilities cost another 76.3 s and 141.6 s (30 SVC fits each). (ii) Model size: 65.1 % / 62.6 % of the training rows are support vectors — 13,663 and 13,140 stored rows × 32 features — so the "model" is most of the customer file, as with KNN, rather than 33 numbers. (iii) Prediction is O(n_SV × d) per client: scoring the 8,990 test clients took 7.807 s for the RBF and 1.521 s for the libsvm linear kernel (libsvm evaluates the kernel expansion even for a linear kernel), versus 0.006 s for the same linear model held as one weight vector — a 253.5× gap. For a bank scoring millions of accounts a kernel SVM is only defensible if it clearly out-ranks the linear models — and here it does not.

8. **The fast alternative (`svm_linear_calibrated`).** `LinearSVC` (liblinear) solves the linear SVM in the primal with a trust-region Newton method: 5 iterations, 0.50 s including Platt scaling — 49.6× faster to fit and 253.5× faster to score than the libsvm linear kernel — and, with sklearn's default squared-hinge loss, it matches logistic regression (test AUC 0.7627 vs 0.7636, AP 0.5150 vs 0.5234, Brier 0.1391 vs 0.1383). Its full-training-set CV AUC is flat in C (0.7611 / 0.7610 / 0.7610 / 0.7610 for C = 0.01 … 10), so the inherited C = 0.01 is as good as any. As a check that liblinear really is the same model as libsvm's linear kernel, the script also fits the hinge-loss `LinearSVC` at the same C: its probabilities agree with the libsvm model to 1.1e-04 on the training rows and it has the same single-feature `coef_` (`extra.hinge_loss_variant`; compared on training rows only in the current script). Process disclosure: in an earlier iteration of this script the hinge-loss variant was itself test-scored (test AUC 0.7406) before being replaced by the squared-hinge model; the squared-hinge choice rests on the full-training-set CV comparison (0.7611 vs 0.7266) and on the task's `LinearSVC` specification, not on that test score. If a linear SVM is wanted in production this is the one to use — but the report can say plainly that it adds nothing over logistic regression.

9. **Implementation notes.** (1) scikit-learn 1.9 deprecates `SVC(probability=True)` (removed in 1.11) and recommends `CalibratedClassifierCV(SVC(), method='sigmoid', ensemble=False)`; that replacement is used for all three models. It is the same procedure as libsvm's internal Platt scaling (5-fold CV decision values → one sigmoid → refit on all rows), but seeded through `CV`, and `predict_proba` is an exact logistic function of `decision_function` (max reconstruction error 0.0e+00 in `extra.platt`). (2) Training out-of-fold probabilities for the threshold tuning inside `evaluate()` come from the standard **nested** `cross_val_predict(predict_proba, cv=CV)` of the Platt-scaled pipeline on the full training set (30 base fits per model): inside every outer fold the SVC is refitted on 5 inner folds, the sigmoid on the inner out-of-fold decision values, and the row being scored is seen by neither (`extra.oof.method`); `oof_auc` in the JSON is the AUC of those probabilities pooled over the outer folds and `extra.oof.per_fold` records the AUC inside each fold (bullet 3). The cheaper shortcut used in an earlier version (5 decision-value fits mapped through the final model's sigmoid) was dropped: it is in-sample for the sigmoid and it cost 47 s. (3) `evaluate()` is called exactly once per final model and nothing touches the test set before it; the only test-set work afterwards — prediction timing, distinct-value counts and the 3-dp / MAX_DELAY-alone check of bullet 3 — is computed from the `p_test` vector `evaluate()` saved and appended to `extra` under keys ending in `_after_evaluate`. (4) At most two workers anywhere (`n_jobs=2` in `cross_validate` / `CalibratedClassifierCV`; the outer `cross_val_predict` loops are sequential; BLAS threads pinned to 1).

10. **Caveats.** (i) Subsample tuning is only approximately transferable: an SVM's effective regularisation scales with C × n, so C = 0.01 tuned on 4,800-row folds is about 3.5–4.4× less regularised on the 16,780-row calibration folds / 20,975-row refit; a C rescaled by n_sub/n_full, or tuning on more rows, would be the next step — both outside the prescribed protocol. Subsample CV AUCs (0.7629, 0.7681) should be compared with the logistic value on the same rows (0.7650), not with the full-data 0.760, and the RBF transfers to the full training set almost unchanged (within-fold OOF 0.7635). (ii) The gaps to logistic regression (-0.001 to -0.013 test AUC, -0.008 to -0.029 AP) are of the same order as the fold-to-fold sd (0.005–0.011); a paired bootstrap on the saved `p_test` vectors would be needed to call any of them significant — the honest summary is "SVMs ≈ logistic, never better, and the libsvm linear kernel is a degenerate special case". (iii) Only the 22 grid cells prescribed (+4 boundary probes) were explored; γ between 0.003 and 0.01 with C ≈ 0.3–3 might add a little, and the heavy-tailed BILL/PAY amounts were standardised but not log-transformed, which is what an RBF distance is most sensitive to. (iv) SVMs give no coefficients (RBF) or degenerate ones (hinge), so they add nothing to the explanatory part of the report; the squared-hinge model's coefficients are the only interpretable output and they mirror the logistic top features. (v) Timings are single-run wall-clock values on a shared laptop with other scripts running concurrently and vary by ±50 % between runs (this run: 24.6 s / 47.3 s for the two libsvm Platt fits; the previous run of the same code path measured 151.2 s / 41.9 s); every metric is seeded and reproducible bit-for-bit.
